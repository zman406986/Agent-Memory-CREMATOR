template v1 · 105-task results
  • Cost USD is the claim. It is the host's recorded price where available, otherwise computed from token counts at $0.15 / $0.003 / $0.60 per M uncached / cached / output (official off-peak rates).
  • Token totals and dollars move apart because the ask lane is priced by its cache split: 83–86% of the ask prompt is cached at $0.003/M, the rest at $0.15/M.
  • Ask triggers count threshold-crossing passes, not files. Compare a continuation with its own predecessor row, not with an earlier campaign.
  • Tokens removed (est.) is one estimated-token number per row. Product rows are ledger bytes divided by 4; vanilla rows are the host pruner's own shadowed-token count. The two are estimates on the same token scale but not the same measurement. Exact figures and their sources are in Notes.
  • Token columns are sums over every request. The context at one moment is one request's billed prompt: product peaks 247–255k, vanilla 319.7–319.8k. The host compacts near 320k.
  • The vanilla pruner drops old results in bursts: 42 events in 2 bursts (206k tokens) in r1. Each burst rewrites the cached prefix, so the next request pays 159.7k and 100.8k uncached. Roughly a wash in dollars; its value is delayed compaction.

Column guide
  • Columns: click a column header to hide it; a hidden column shows +. A group chip toggles the whole group; Show all columns restores every column. More numbers reveals class, model, billed prompt, the token breakdown, and the keep/forget/ratio detail. Notes open under the row.
  • Token cost: cost USD is the headline and stays visible; billed prompt sits behind More numbers. Raw input, cached input, cache write, output and reasoning are the five subcolumns behind Token breakdown. Billed prompt = raw input + cached input + cache write. Cost USD is the host's own cost; leave it blank when the host records no price.
  • Run shape: compactions are completed host compactions; put the count and request numbers in the cell. Ask triggers are successful ask fires (generate + parse).
  • Removal: keep and forget lines are counted over answered ask rows. forgetall forgets L; a full-range keeplines keeps L; a partial keeplines keeps its named spans and forgets L minus those spans. Ratio = keep ÷ forget. Tokens removed (est.) is one estimate per row: product rows are ledger bytes ÷ 4 (the applied removal's byte volume at 4 bytes per token), vanilla rows are the host pruner's own shadowed-token count. The exact figure and its source are in Notes.
  • Outcome: a completed run meets the brief's file count and BENCH-DONE. A budget stop is a censored partial and must say so.
